# The dependency set the production image is running, frozen.
#
# The Dockerfile installs this package from source, so `pip install .` re-resolves
# every dependency on every build. `fastmcp>=3.4` in pyproject.toml is a floating
# range, and rebuilding an image untouched for weeks would have pulled fastmcp 4.x
# and mcp 2.x onto a live connector — a major version jump nobody asked for, on a
# server whose code reaches into SDK internals (the session manager, the OpenAPI
# provider, the Apps resource config).
#
# So the build is pinned to what production actually runs. Read as constraints
# (`pip install -c`), these do not add dependencies: they only say which version to
# take when something is already being installed. Upgrading is then a deliberate
# edit of this file, with the test suite as the gate — never a side effect of
# rebuilding for an unrelated change.
#

# is set), at the version the test suite runs on (.venv, 2026-10-02). The 0.4.12
# container has no redis to read one from.
