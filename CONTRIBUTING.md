# Contributing

Thanks for your interest in `pexafy-mcp`.

## Development setup

Requires Python 3.12+.

```bash
./run.sh setup        # venv + editable install (with dev tools) + seed .env
./run.sh dev          # run over stdio (Claude Desktop/Code)
./run.sh run          # run the HTTP server locally
./run.sh test         # run the offline test suite (pytest)
./run.sh inspect      # open the MCP Inspector
```

## Before opening a PR

```bash
.venv/bin/ruff check src/ tests/   # lint (also run in CI)
./run.sh test                      # tests (also run in CI)
```

CI runs the same two checks (`.github/workflows/ci.yml`). Both are offline, and the tests
are built to stay that way: `tests/conftest.py` forces a harmless configuration before
anything is imported (the API points at an unresolvable host, no key, no thumbnail
proxy), ignores any `.env`, replaces the Pexafy API in memory (the `fake_api` fixture),
and fails any test that opens a network connection or resolves a host name — even when
the code under test swallowed the refusal. No Pexafy backend is needed, and a test that
needs other settings reloads a module with `reload_with_env`, which puts it back
afterwards.

## Project layout

See **How it works** in [README.md](README.md). In short: the text search is generated
from the vendored `src/pexafy_mcp/assets/openapi.json` and tuned for an LLM in
`tooling.py`; the other four tools are written by hand in `server.py`, `selection.py`
and `linking.py`. Importing the package does no network I/O; all construction happens
in `build_server()`.

## Regenerating the vendored assets

The OpenAPI snapshot and the inlined ext-apps SDK bundle are regenerated by maintainers
with `./prepare.sh` (needs `PEXAFY_API_BASE_URL` in `.env`; it downloads from that API
and from jsDelivr). Review the diff and commit the refreshed `assets/`.

## Conventions

- Keep the LLM-facing tuning (descriptions, examples, value sets) in the MCP server;
  keep API facts (routes, types, internal fields) in the Pexafy API schema.
- Tool names live in one registry, `tooling.PUBLIC_TOOL_NAMES`; text that names a tool
  interpolates it from there. A tool or parameter that is renamed or retired keeps
  working for existing hosts through `compat.py`.
- Instructions and tool descriptions stay under 2,048 characters, where Claude Code cuts
  them; `tests/test_surface_limits.py` checks it.
- The version is written in `pyproject.toml`, `src/pexafy_mcp/__init__.py` and
  `server.json`, and `CHANGELOG.md` needs an entry for it; `tests/test_version.py`
  checks all four agree.
- Every environment variable the server reads is documented in `.env.example`, with its
  default.
- Never commit secrets. `.env` is git-ignored; use `.env.example` for documentation.
