# Contributing

Thanks for your interest in `pexafy-mcp`.

## Development setup

Requires Python 3.12+.

```bash
./run.sh setup        # venv + editable install (with dev tools) + seed .env
./run.sh dev          # run over stdio (Claude Desktop/Code)
./run.sh test         # run the offline test suite (pytest)
./run.sh inspect      # open the MCP Inspector
```

## Before opening a PR

```bash
.venv/bin/ruff check src/ tests/   # lint (also run in CI)
./run.sh test                      # tests (also run in CI)
```

CI runs the same two checks (`.gitlab-ci.yml`). Both are offline — the tests build
the server from the vendored OpenAPI snapshot, so no Pexafy backend is needed.

## Project layout

See the **Architecture** section of [README.md](README.md). In short: the search
tools are generated from the vendored `src/pexafy_mcp/assets/openapi.json`, then
tuned for an LLM in `tooling.py`. Importing the package does no network I/O; all
construction happens in `build_server()`.

## Regenerating the vendored assets

The OpenAPI snapshot, facet value sets, and the inlined ext-apps SDK bundle are
regenerated by maintainers with `./prepare.sh` (needs `PEXAFY_API_BASE_URL` and a
facet key in `.env`). Review the diff and commit the refreshed `assets/`.

## Conventions

- Keep the LLM-facing tuning (descriptions, examples, value sets) in the MCP server;
  keep API facts (routes, types, internal fields) in the Pexafy API schema.
- Never commit secrets. `.env` is git-ignored; use `.env.example` for documentation.
